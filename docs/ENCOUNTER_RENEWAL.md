## Identity, bounded learning and anti-churn

Root encounterRenewal state stores slot-aligned occurrence identities separately from legacy descriptive master/party string arrays. Ordinary sales prepend identities just like the existing installed loadout; explicit replacement exchanges only its chosen identity; wear preserves surviving positions, including shifts after oldest-slot removal. Duplicate SKU occurrences remain distinct; repeated rooms at the same occurrence deduplicate.

Per master: at most three current requests, twelve recent terminal explanations, a retained minimum admitted observed mass and a monotone settled-day marker. Equal/easier observations cannot regenerate requests after payment/decline/expiry/history rotation or manual A-to-B-to-A changes. A strictly smaller mass actually bypassing a surviving current ordinary installation can create a new epoch. This conservative rule intentionally does not model all motives for renewal. New, unobserved counter families are not silently added to improve bot metrics.

OPEN becomes paid only through a successful relevant transaction, with its contract identity. Decline is a persisted non-purchase disposition; defer leaves the same OPEN request (the visit-only UI message is not a persisted setting). Expiry is twelve elapsed campaign days and is derived at every consumer boundary; actual later settlement writes terminal status. Removal/changed mechanics stales the occurrence. Forecast, review, cancel and unsuccessful payments never consume it.
