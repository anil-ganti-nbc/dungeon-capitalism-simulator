## Important functional gaps beyond counts

### Learning and actual consequences

`simulateRegionExpedition` constructs room outcome/learning strings (`simulation.ts:339–659`). `resolvePostRaidClients` updates budgets, wear, trust, text memory and desired text (`economyEngine.ts:385–414`), but does not update members or structured knowledge. `knownHeroCounters`/`observedTraps` are not inputs into the encounter algorithm. All those structured fields remained unchanged in the 100-policy sample; the source path explains why. This undermines the intended learned attack/counterattack economy.

Finite purchasing is real, but acceptance is largely capacity/trust/budget (`economyEngine.ts:118–150`, `219–241`), not a price/value judgement tied to demand text. Demand sentences currently cannot make a full installation accept a useful upgrade. See `RENEWAL_ECONOMICS.md`.

### Forecasts and progression

`predictExpeditionForecast` directly calls the actual simulator and returns exact rooms/loot (`simulation.ts:729–746`); `App.tsx:179–196` invokes it before commitment. This is omniscience, not the intended inspectable uncertainty/intelligence progression.

The solo Catalyst checks Blackspire unlocked plus 2 custom brews, 2 traps, 2 master and 2 hero contracts (`progression.ts:3–16`); none must have been earned on Hard or prove effective offensive/defensive engineering. It mandates bilateral counts, rather than the bible's multiple partisan/neutral commission paths. The runner adds its own tenure/day conditions (`campaignRunner.ts:357–387`) that the shared UI command does not enforce. R1's genuine UI Expert-by-Day-3 is therefore a progression warning, not an accepted design result. Entitlement persistence/ledger exists, but qualifying commission remains incomplete.

The shipped charter costs are 4,500g and 14,000g (`world.ts:43,58`), not the bible's provisional 5,000g and 35,000g. Record the discrepancy; do not silently restore/rebalance numbers without comparative evidence.

Blackspire ending buttons set a resolution flag (`App.tsx` callback around 1055); this is not an earned political investigation with mechanically differentiated outcomes. Core ending remains required on Hard, never held behind Expert.

### Host technology and Android

The source is an existing React/Vite/2D Canvas/PWA foundation, not Godot/native APK. The selected art plan explicitly retained that host; no unilateral migration or replacement is warranted. Use the current host to establish mechanics, then separately resolve whether a native wrapper can meet lifecycle/performance gates or an engine migration is necessary. Do not call a browser wrapper an actual game-engine implementation without that decision.

Browser offline cold reopen, save rotation and touch tests are positive evidence. They do not establish Android OS-kill safety, picker behaviour, installed APK performance or real-device accessibility. Audio/original production art is not complete. A/A0 direction remains selected; production still requires separate explicit operator authorisation.
